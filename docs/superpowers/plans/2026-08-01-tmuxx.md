# tmuxx Runner and Typed Wrappers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `internal/tmuxx` as the sole typed, testable boundary for the exact external-command contracts in design spec §13.

**Architecture:** A `Client` owns a small stdout-only `Runner`. `RealRunner` delegates to `os/exec.CommandContext`, while `FakeRunner` deep-copies calls and consumes FIFO scripted responses. Typed wrappers construct the canonical tmux/ps argv, parse every structured response inside `tmuxx`, and expose only `DeliverPayload` for keystroke delivery.

**Tech Stack:** Go 1.26 standard library only (`context`, `errors`, `fmt`, `os/exec`, `strconv`, `strings`, `sync`, `time`, `testing`).

## Global Constraints

- The approved design spec and §13 canonical argv table override `docs/brief.md` where they differ.
- Every tmux target is a resolved `$N`, `@N`, or `%N` ID; no target name and no `=` prefix reaches `-t`.
- Rows 1–13 execute `tmux`; row 14 executes `ps`; no shell is invoked.
- `DeliverPayload` is the only delivery surface and owns its fixed delay; no generic send-keys API is exported.
- Structured stdout is parsed inside `tmuxx`; malformed fields return contextual package errors.
- `ProcessName` maps command exits and empty output to `ErrProcessUnavailable`, while context and process-start failures remain ordinary errors.
- Go standard library only; `go test ./...` and `go vet ./...` must pass.
