# Attach Command Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `agentctl attach` so it safely attempts iTerm2 tmux control-mode attachment to one resolved, compatible agentctl session.

**Architecture:** Add an `internal/attach.Executor` with a pre-resolution environment check and a post-resolution ownership/control-mode operation. Wire it into `cmd/agentctl` so environment failures precede the existing session resolver, while all tmux work remains behind `tmuxx.Client` and tests inspect recorded argv.

**Tech Stack:** Go standard library, existing `internal/session` resolver, existing `internal/tmuxx` typed client and fake runner.

## Global Constraints

- The approved design is authoritative; apply §1.1, §4.1, §6.4, §9, §12.6, §13.1, and §13.2 row 13 without restating their contract details here.
- Follow the repository threat model in `SECURITY.md`; attachment remains an accident-prevention mechanism, not a same-user security boundary.
- Use only the Go standard library and existing internal packages.
- Every negative path must prove no session-creation operation occurred.
